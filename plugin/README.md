# LifeCard（DSH 插件）

本地优先的人物档案库。把现实里的人、虚构角色和他们之间的关系写成可读的 Markdown，放在你可以随时打开、随时带走的一个文件夹里。

**四个入口，两条链路。** 首页那排按钮就是它们：

```
① 导入        角色卡 PNG / JSON / CHARX → 直接出卡        （纯格式搬运，不调模型）

② 聊着建      它问，你答 → materials/ ─┤
③ 一段文字    访谈稿/聊天记录/日记 → materials/ ─┤
                                  ↓
        整理材料 → 引文校验 → 提案 → 你勾选 → 写进卡
                                  ↑
④ 新建        手写，不经过 AI           （这条路没有闸门，因为句句都是你说的）
```

② 和 ③ 产出同一种东西（材料），之后走**完全相同**的一条链。这是它能成立的原因：一套闸门，两个进料口。

> **界面上的按钮名**：首页「新建」「聊着建」「导入」；导入页里分「角色卡文件」和「一段文字」两个标签；有材料后首页右边会出现「整理 N 份材料」；右上角「检查一下」。本文档里说的「访谈」= 聊着建、「分析」= 整理材料、「体检」= 检查一下。

## 安装

这是一个 DeepSeek Harness 插件，跑在侧边栏里。

```bash
# 从本地目录装进你的 profile（替换成实际路径）
dsh plugin --profile desktop add /path/to/LifeCard/plugin
```

装完**重启 DSH App**（桌面版的 profile 被它独占，改了文件也不会热更新，必须重启）。

重启后，**左边那排图标里会多一个 Life Cards**（一个打开的小本子）。点一下，中间主区域就是它。

另外，如果你装了 `dsh-better-sidebar`（侧边栏底座），**右边那栏的「+ / 新标签页」列表里也会有一条 Life Cards**，可以把它开在右边长期看着。左边那个入口不依赖它——没装底座也照样能用，只是少了右边这个。

## 第一次打开

它会问你要一个文件夹。选一个空目录，或者一个已经有 `lifecard.config.json` 的旧库。

这个文件夹就是全部数据：

```
我的档案/
├── lifecard.config.json     名字、语言、上次选的分析模型、你写的「想要什么样的人」
├── people/                  主世界的人          妈妈.card.md
├── self/                    我自己 + 偏好透镜
├── relations/               有向关系边          mama--self.relation.md
├── worlds/                  世界观；导进来的世界书落成 worlds/<名字>/world.md
├── systems/                 消费协议（扮演 / 访谈 / 写作素材）
├── materials/               原始材料，只追加、不可编辑
├── interviews/              访谈账本（问答过程，不是结果）
├── proposals/               建议清单 + 你勾的那几项
│                            两份文件：.md 给人看，.json 给程序读，
│                            还有一个 .checked.json 记你在界面上勾了哪几条
├── story/                   小说章节与状态账本
│   ├── chapters/
│   ├── state/ledger.jsonl
│   ├── state/snapshots/
│   └── threads.jsonl
├── redactions.jsonl         删除墓碑，只追加
├── assets/                  头像（<卡 id>.png）和插图，导出时打进卡里
└── .lifecard/
    ├── index.json           派生索引，删了能重建
    ├── raw/                 导入的原件
    └── snapshots/           每次保存前的全文快照
```

排法在 `SPEC.md` §1 里定死了，不要自己加目录。

**它就是一个普通文件夹。** 用 Obsidian 打开，全文搜、双链、标签、手机版全都有——不需要本插件也能读写。

## 怎么用

### 从零建一张卡（最常用的路）

点 **聊着建**，填名字、选关系类型，然后开始答。

> 也可以在自己对话里用 `lifecard-interview` 这个 skill 问同样的问题——它产出同样的材料，只是跑在对话框里而不是侧栏里。

```
1 / 12  你妈最像哪一种？
        ① 嘴上嫌弃，手上不停
        ② 很少说，但记性极好
        ③ 什么都问，问完自己拿主意
        ④ 都不像，我自己说
```

选完它会追问一件具体的事：

```
那么「嘴上嫌弃、手上不停」——最近一次这样，是什么时候？
（要一件具体的事，不是评价。跳过也行）
```

**四条规矩：**

1. **每题都有「都不像，我自己说」。** 没有这一项，你会被逼着从四个错的里挑一个最近的，最后得到一张写着别人妈性格的卡。
2. **随时可以跳过。** 说「不想说」的题记进账本，以后永不再问。
3. **一次最多 3 个问题。** 答完一句就能停，下次接着来——它记得停在哪。
4. **它不替你总结。** 不会给你「她是一个温柔而坚韧的母亲」这种句子。原话进 `materials/`，概括由你自己写。

### 导入已有的酒馆卡

点 **导入**，把 PNG / JSON / CHARX 拖进去，可以一次拖多张、也能拖整个文件夹。

- **不认识的字段原样保存**（V2 规范要求「绝不能销毁」），导出时写回
- 原始文件复制到 `.lifecard/raw/`，方便核对
- **不执行宏、不跑 decorator** —— 这是编辑器，不是播放器
- 整个导入过程**不联网、不调模型**
- 支持 `.png`（带 `chara` / `ccv3` 两种标签）、`.json`（CCv2 / CCv3 / V1）、`.charx`（zip）

### 把材料变成卡

点 **整理材料**（首页右边那个按钮），选一张卡和要用哪些材料，然后：

1. 模型读材料，产出每一条都带**原文引文**的建议
2. **程序做机械校验**：引文必须在材料里逐字出现，对不上的整条丢弃
3. 你在清单上勾选，点「就用这 N 条」

**AI 全程不能直接写卡。** 它只能写 `proposals/`，勾选和落盘是你的动作。这不是流程偏好——模型会把「它推断的」说成「材料里有的」，而且说得比人更自信。三个月后你分不清哪句是本人说的，就再也救不回来了。

### 导出

- **导出 PNG**：`chara`（V2）与 `ccv3`（V3）两个 chunk 来自**同一个源对象**，V3 是 V2 的严格超集。SillyTavern 的 `read()` 以 `ccv3` 优先，两份独立投影会让同一张卡在两个前端里变成两个人。
- **导出 JSON**：CCv3 格式。

## 为什么这些设计是这样的

| 决定 | 理由 |
|---|---|
| 文件是唯一真源 | 没有任何 KV 缓存充当第二真源。你手改 Markdown，插件立刻看得到 |
| `materials/` 只追加 | 它是原话的存档，所有断言都要能追回这里 |
| 访谈不抽字段 | 抽取归「分析」，那里才有引文校验门。访谈也抽就等于开一条没校验的旁路 |
| 删除留墓碑 | 撤回要真的能撤回：读取、导出、分析输入都先过 `redactions.jsonl` |
| 快照存全文不存 diff | 快照是审计依据；diff 快照没法审计，还会和墓碑过滤打架 |
| 无账号、无云同步 | 没有「找回密码」——文件丢了就是丢了，请自己备份 |

### 它明确不做

- ❌ 不替你生成整篇人物传记
- ❌ 不猜材料里没有的东西（那些进 `gaps` / `questions`，是另一类数据，不带事实地位）
- ❌ 不自动改稿
- ❌ 不做手机端随手记（手机浏览器没有文件夹写入 API，iOS Safari 与 Chrome for Android 都不支持 `showDirectoryPicker`）
- ❌ 不做自造问卷 UI（访谈就在宿主的对话框里跑）
- ❌ 不做情感计算、不自动打分好感度

## 分析用哪个模型

**默认用你 DSH 里已经接好的模型，不用配 key。** 它会：

1. 先按插件配置里的 `defaultAnalysisModel`（形如 `provider/model`）
2. 否则按「本机实测能出文本」的 provider 顺序找
3. 一个都不行就**明确报错**，并告诉你改用「手工建卡」

要指定路由，在 profile 的 `cordis.patch.yml` 里给这一行加 config：

```yaml
- id: lifecard
  name: 'dsh-lifecard'
  config:
    workspace: /Users/你/我的档案
    defaultAnalysisModel: deepseek-official/deepseek-flash
```

## 开发

```bash
node test/all.mjs        # 全部测试（736 项）
node test/roundtrip.mjs  # YAML ↔ Markdown 往返
node test/codec-test.mjs # 酒馆卡编解码 + 双 chunk 同源
node test/store-test.mjs # 文件层：墓碑、提案、引文门、采纳
node test/client-smoke.mjs # 浏览器 bundle：加载、注册、渲染
```

核心逻辑零依赖、零网络：

| 文件 | 职责 |
|---|---|
| `lib/core.js` | schema、YAML 子集、卡片解析、校验、覆盖率、引文门 |
| `lib/codec.js` | CCv2/V3/PNG tEXt/CHARX 编解码，保真，双 chunk 同源 |
| `lib/store.js` | 工作区读写、快照、墓碑、提案、采纳、doctor |
| `lib/prompts.js` | 访谈问题库、分析提示词 |
| `lib/index.js` | 宿主路由 |
| `lib/client.js` | 侧边栏界面（`__ModuleLoader__` 格式） |

数据契约见仓库根目录的 [`SPEC.md`](../SPEC.md)。

## 数据安全

- 数据只在你自己选的文件夹里，没有默认云同步，没有遥测
- 导入与导出不联网；只有「分析」这一步会调模型
- 导出成可传播格式时会检查 `consent`（这张卡的对象是否知情同意）；本地保存、编辑、搜索一律不检查
- 已故的人**不做任何限制**，只有一次性的说明页与 `doctor` 统计
- 删除留墓碑，但**挡不住已经导出的文件**——`doctor` 会告诉你哪些原始文件仍含已撤回内容
